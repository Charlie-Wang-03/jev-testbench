# 发现

[English](findings.md) | **简体中文**

本实验台关于 TypeSafe Jev 学到了什么，按每一项能承载多大权重来组织。

请与它的对偶章节一起阅读：[你不能从这个仓库得出的结论](../../README.zh-CN.md#7-你不能从这个仓库得出的结论)。
这里的每一条发现都是**本地测量**，除非另有明确标注 —— 一份 payload、一个账号、一次会话、一个模型版本。

**证据：** [42 条核心记录](../../results/usage.jsonl) ·
[12 条 P3 记录](../../results/p3_boundary_locus/usage.jsonl) · 实际解析模型 `jev-1.13.0`

## 1. 已复现

在此观察到、且与 TypeSafe 文档所描述一致的行为。这些都不是新发现 —— 这正是把它们单列出来的原因。

### 类型化输出的语义

**42 / 42** 条响应全部通过 schema 校验且只有类型化答案；没有任何答案携带自由文本字段。**45** 个
`Choice` 答案中，返回的标签每一次都是概率最高的选项，没有反例。**29** 个 `Score` 答案中，**24** 个
在 0.006 以内复现了概率加权均值，且没有任何 `Choice` 标签落在给定 criteria 之外。

`Noul` 答案**不**携带单独的 `confidence` 字段 —— 只有两种结果时，单个概率已经描述了整个分布。每个
`Choice` 和 `Score` 答案都携带一个，而且它们是并排报告的两个不同的数字：在 `01_primitives` 中，胜出
概率是 0.45，而 confidence 是 0.26。

> **这个结论值多少。** 这是良性 payload 上的 schema 合规，在少数几个合成用例上测得。它是支持类型安全
> 主张最弱的一种证据。它不说明事实正确性，而厂商自己公布的「零幻觉」数字被厂商自己标注为**非经验性**
> —— 任何引用都必须带上这个限定。

### 对共享同一 state 的问题做批处理

把五个问题针对同一个 state 放在**单次**请求里，消耗 **816** 输入 token。把同样的五个问题拆成**五次
独立**请求，消耗 **3,480**。即合并输入比 **4.26×**、节省 **76.55%**，且两个臂之间 **10 / 10** 个
选中值完全一致。

这个节省是真实的，而且很大。但有两件事它不是：

- **不是通用批处理倍率。** 这份 payload 里的每个问题都读同一个 state，而这恰恰是这个节省所依赖的条件。
- **不能与厂商公布的倍率相比较。** TypeSafe 自己的数字描述的是另一种 workload —— 问题数不同、payload
  不同、分母不同、会话不同。把两者并排写成「官方 vs. 实际」是范畴错误，
  [P1 审计](../audits/P1_OFFICIAL_CLAIMS_LOCAL_EVIDENCE.md)明确指出了这一点。

这个*现象*是预期之中的 —— 它就是直白的同 state 摊销，而且公开的第三方测量在这同一模式上走得更远
（它们变化了批大小；本实验台没有）。见[被否决的发现](#3-负面与被否决的发现)。

### 指令与 criteria 的具体程度会移动答案

在一个**逐字节相同的 82 字节 state** 上，仅改变问题的措辞就把一个 `Noul` 从 **0.75**（模糊决策边界）
移到了 **0.20**（明确）—— 在同一个 state 字节上，0–1 概率的差异为 **0.55**。

在这份 payload 上这是一个真实的、很大的效应，且与 TypeSafe 已记录并给出补救办法的一个失效模式一致。
有两个局限随之而行：两个臂是**一起**改动了 *instruction* 和 *criteria* 的措辞，所以这个设计无法把位移
归因到其中任何一个；并且 0.75 和 0.20 都不是 ground truth，因此两个臂都无所谓「正确」。

那个未被归因的 0.55，后来成了 P3 的问题。

### 相同请求的重复性

两个 payload 上共十次逐字节相同的请求。胜出的 `Choice` 标签**从未切换** —— 一份 payload 上 5 / 5，
另一份上 5 / 5，若把第二份复用的那条历史记录也算上则是 6 / 6。

在那个稳定标签之下，分布移动了。在边界清晰的 payload 上，`Noul` 在五次重复间变化了 0.01。在量表中段
的 payload 上，前二名间距最多移动了 **0.07**，`Score` 落在 **1.58–1.63**，并且有一次重复出现了前两名
之间的**精确并列**。

> **标签稳定不等于分布固定。** 这句话在这里被写下来，随后在 P2 中因**不够新颖**被否决 —— 底层事实已由
> 官方文档记载，而公开复现所带的数据量比我们更大。它被记为一条已复现的观察，而不是一项发现。见下文。

## 2. 工程经验

从搭建与运行这个实验台中得到的可迁移结论。这些是关于系统设计的，而不是关于模型内部的 —— 本项目没有
关于后者的任何文档，也不去指认任何机制。

### Confidence 是策略输入，永远不是正确性分数

官方文档把校准的适用范围限定在**成组**预测上，并写道 confidence「描述的是模型的答案，而不是该答案正确
的保证」。两个本地用例*说明*了这层限定；它们无法检验它。

本地的警示样本比这条规则更锐利。在 `06_composite_scoring` 中，某个维度在 0–3 量表上得分 **1.62**，
而它的 confidence 是 **0.24**，并且这个维度承载了该 state 综合风险值的 **97.4%**。算术是对的。
confidence 是低的。它们本来就是两个不同的问题，而一个把低 confidence 读成「错」、把高 confidence
读成「对」的策略，读错了数字。

这也正是 `composite.py` 禁止 confidence 参与任何算术的原因：confidence 被记录、被展示，除此之外不被
用于任何用途。

### 语义路由不等于执行授权

这是本实验台产出的最有用的一个模式，而它来自一次与设计预期**相反**的运行。

在 `12_function_routing` 中，模型 4 / 4 次匹配到预期函数、4 / 4 次匹配到预期参数。运行前冻结的策略
**扣下了全部**路由，因此 `HANDLERS[name](argument)` 从未在真实答案下被抵达。也没有任何替代发生。

两件事都值得同时握住：模型的环节是成功的；而授权决定是在 Python 中、在事后作出的，它说了「不」。任何
把有信心的路由当作行动许可的系统，都已经删掉了产生这个结果的那一层 —— 而这四次扣留完全可以由本仓库自
己选定的常数解释，与模型做了什么无关。`routing.py` 在常数旁边就是这么写的：*文档里没有任何地方说 0.8
就是那条线*。

那个计数 —— **4 / 4** —— 是合成用例上的计数，**不是准确率**。

### Fail closed，并记录失败

凭据缺失、为空、格式错误、重复或不可读，会在发出请求**之前**终止运行。注册表之外的标签、缺失的参数、
落在所选函数冻结集合之外的参数，全都拒绝执行。一个无法继续的运行不会部分推进然后指望运气。

记录规则形状相同：**失败的调用仍是一条记录。** 它携带自己的位置字段与尝试次数，因为这些是在请求发出
之前就写好的。日志只追加，「坏」行也是数据。

### 溯源必须是机制，而不是承诺

本仓库有若干性质之所以成立，是因为有某种机械性的东西在保证，而不是因为某份文档礼貌地提出了要求：

- `retry_count` 永远是 `null`，因为 SDK 把这个 header 设在*请求*上，而 recorder 读的是*响应*。该字段
  被保留只是为了让旧行仍然可读，从不回填，且其中的 `null` 意味着**未报告** —— 永远不是「没有发生重试」。
- `transport_attempt_count` 在本地统计线路层尝试次数，并由 `attempt_count_source` 指明机制。它只授权
  一句结论：*本次调用未被观察到重试。* 它**不**授权「这是纯模型延迟」—— DNS、TCP、TLS、连接池状态、
  服务端排队、上游负载与本地调度都在同一个时间窗内。
- 位置字段（`case_sequence_index`、`logical_request_index_in_run`、`client_session_id`、
  `is_first_request_in_client_session`）的存在，是因为在前三个 A/B 实验中，位置与臂身份被完全混淆。
  字段缺失意味着**未记录**，绝不意味着零。
- `model_requested` 与 `model_resolved` 都被记录，因为别名会移动，而只有响应能说明到底是哪个模型回答的。

可推广的经验是：如果某个性质重要，就把它放到机器会检查的地方。文档里的一句注释是约定，而约定恰恰就是
那种会悄悄不再成立的东西。

### 只要重新计算，派生文件就不会漂移

`results/` 下除两份权威日志以外的每个文件都是按需从日志重建的。`final-report` 在写出的同时重算每一个
数字，因此一份与日志不一致的报告是可被检测为过期的，而不是悄悄变成权威。权威文件被纳入版本控制；派生
文件被 gitignore，正是为了防止它们成为第二个事实来源。

## 3. 负面与被否决的发现

**这一节才是把这个项目区分出来的部分。** 这些是看起来有意思、被认真调查过、但没能存活下来的结果。

P2 用同一把尺子审查每一个候选：*它相对于 TypeSafe 的公开材料是否新颖，**并且**是否得到我们自身数据的
支持？* 七个候选被淘汰。其中**本地效应量最大的两个**是基于已有先例被淘汰的，而不是基于本仓库自身的
数据。正如该审查所说：

> 没有任何候选因为不好看而被否决，也没有任何候选因为有意思而被保留。

### 被否决

| 候选 | 类别 | 为什么没能存活 |
|---|---|---|
| 标签稳定、分布移动 | 官方已记载 | **两条理由各自独立地充分**：它由厂商自己报告过的标签翻转与非零标签间离散度所官方蕴含；**并且**一项公开复现把同一请求发送了五次，在约 1,490 次捕获调用上公布了抖动下限。厂商没有用我们这句话；但这句话本身不是那个东西。 |
| 批处理降低输入 token | 独立复现 | 预期的同 state 摊销。公开的第三方测量既报告了批大小为 20 时的每行 token 成本，**也**给出了准确率—批大小曲线 —— 一项比本实验台走得更远的研究，本实验台从未变化批大小。 |
| 0.75 → 0.20 的指令效应 | 官方已记载 | 已记录失效模式的直接实例，且文档已给出补救办法。每个臂都是 n = 1，两个值都不是 ground truth。这个*现象*没有死 —— 死的是它的*归因*，归因移交给了 P3。 |
| 模糊用例越过了 0.60 门槛 | 我们自己的策略 | 纯粹是对本仓库自己选定常数的阈值算术。公开的 k=3 表达式**精确**复现了 0.61，且返回的间距是 0.74 对 0.26 —— 那个「模糊」是 state 设计的属性，不是返回分布的属性。 |
| Fan-out 用输入换输出 | 非 Jev 发现 | 通用的推测执行权衡。而且在本产品上，「浪费掉」的资源是**输出** token，公布的价格表把它定价为零 —— 所以「未消费却付了钱」在这里没有成本含义。计费的那个量反而**下降**了 400 个输入 token。 |
| `confidence` 无法由 `probabilities` 重算 | 非 Jev 发现 | API 两位小数舍入的产物，不是模型的行为。在 74 个答案中有 4 组碰撞 —— 最刺眼的是 `(1.0, 0.0, 0.0)` 出现 13 次，11 次 confidence 为 1.0、2 次为 0.99。这个发现讲的是**我们的记录**能分辨到什么程度。 |
| 每一条正确路由都被扣下 | 我们自己的策略 | 这些扣留完全可以由这里选定的常数解释 —— 一条 0.8 下限和一条 0.5 复核线。改动其中任何一个常数都会改变结果，而不需要任何模型调用。诚实说法是路由器**按我们的指令**拒绝执行。 |

### 被搁置，随后未被授权

有一个候选是被**搁置**而不是被否决的：*波动是否是边界邻近度的函数？* 中段 payload 每一次重复都在移动；
一个被钉在 1.0 / 0.0 的 payload 则无法移动。它被搁置，一是因为边界无法在没有先导实验的情况下事先定位
—— 因此不满足可证伪性门槛 —— 二是因为这个对比被**天花板效应**混淆：一个被钉在 1.0 / 0.0 的分布没有
移动的余地，所以它的「稳定」是饱和，而不是稳健。在重新设计之前不予公开发表授权。

### 唯一存活的候选，随后返回了零结果

恰好有一个候选通过了审查：**决策边界由哪个输入字段承载 —— instructions 还是 criteria？** 针对字面
阅读失效模式的官方补救办法是作为一个整体给出的，从未被分解；最大的本地效应（0.55）是在两个字段同时
改动下产生的；并且没有找到有对照的公开归因。注意那次新颖性核查的结论是
`PUBLIC_NOVELTY_UNRESOLVED` —— 记为*未决*，绝不是「没有人发现过」。

P3 把它跑了：四个臂、两个字段的 2×2 交叉、每臂三次重复、共十二次调用，设计与阈值在第一次请求之前冻结。

**判定：`P3_KILL_NO_SINGLE_FIELD_ATTRIBUTION`。**

| 臂 | Noul 原始值 | 中位数 | 极差 |
|---|---|---:|---:|
| 都不改 | 0.77, 0.76, 0.75 | 0.76 | 0.02 |
| 仅 instruction | 0.31, 0.33, 0.29 | **0.31** | 0.04 |
| 仅 criteria | 0.37, 0.36, 0.33 | **0.36** | 0.04 |
| 都改 | 0.20, 0.21, 0.20 | 0.20 | 0.01 |

两个单字段臂都移动到了接近明确基线的大部分位置，而它们彼此之间只差 **0.05**，相比之下端到端差距为
0.56。预注册规则（K1）否决了这次归因：没有任何一种「把某个单字段臂当作位移臂」的指派，能使其对侧落在
模糊基线附近。

描述性算术，予以记录但**不是**判定规则的输入：仅 instruction 恢复了 80.4% 的差距，仅 criteria 恢复了
71.4%。端点臂复现成功 —— 原始运行中 0.75 → 0.20 的位移这次以 0.76 → 0.20 回来。

**零结果也是结果。** 正确的总结是*在这个设计与样本量下，该效应无法被归因到单一字段* —— 而不是*边界存在
于两个字段之中*，更不是*criteria 才是关键*。有两条局限在此承重：交叉臂是把一个较宽的字段与一个较窄的
字段配对，而不是两个独立变化的定义（`FIELD_ALIGNMENT_CAVEAT`）；且每臂 n = 3 只支持中位数与极差，
不支持区间估计。

完整推理：[P3 结果](../audits/P3_BOUNDARY_LOCUS_RESULT.md) ·
[P3 预注册](../experiments/P3_BOUNDARY_LOCUS_PREREGISTRATION.md) ·
[P2 审查](../audits/P2_JEV_INSIGHT_TRIAGE.md)。

## 4. 未确立

整个仓库的适用范围边界。这些不是待办事项，而是这份证据能承载的边界。

| 未确立 | 原因 |
|---|---|
| 通用准确率 | 本实验台中不存在任何 ground truth。「4 / 4」是合成用例上的计数，永远不是比率。 |
| 校准 —— 两个方向都没有 | 不存在结果发生率。**本仓库绝不能被引用为验证或证伪了校准。** |
| 模型延迟基准 | 延迟是记录，不是基准。没有声称任何加速，也没有把任何臂称为更快。 |
| 确定性 —— 或非确定性 | 两个 payload 上的少数几次重复不构成确定性裁决。 |
| 通用批处理倍率 | 4.26× 是「所有问题共享同一个 state」的那一份 payload 的属性。 |
| 广泛的幻觉基准 | 这里不探测事实正确性。只测量了良性 payload 上的 schema 合规。 |
| 综合维度的独立性 | 四个维度之间的相关性从未被测量。 |
| 一条经过验证的允许执行 handler 路径 | `ACTUAL_HANDLER_EXECUTION_UNTESTED` 依然成立：在真实答案下，从未观察到一条被允许的路由抵达 handler。 |
| 任何真实的外部副作用 | 所有 handler 都是惰性的。没有写文件、没有发起网络调用、没有发送消息。 |
| 生产安全 | 这里没有任何内容能证明某种模式对真实系统、真实客户数据或真实资金是安全的。 |
| 厂商说法的裁决 | 官方数字被记为关于 TypeSafe 工作负载的说法，绝不会被改写成本地测量。 |

### 证据当前的诚实状态

> 横跨 42 条核心记录与 15 项被主张的官方行为，本实验台**没有任何关于 Jev 的发现，既相对于 TypeSafe 的
> 公开材料是新颖的，又得到其自身数据的支持。** 每一个大的本地效应，要么是在重述一个官方已记载的行为，
> 要么是我们自己 Python 侧策略的产物。

这就是经过 P1、P2、P3 之后的状态。它是一个刻意达成的结果，而不是失败 —— 这个仓库的存在是为了检验发现，
而不是为了堆积发现，而检验结果是否定的。未来的实验可以改变它；到目前为止没有任何一个做到了。

### 一处已知的文档缺陷

P1 审计称「42 / 42」个 `Noul` 答案不携带 `confidence` 字段。在 P3.5 期间直接对照权威日志核验，正确的
计数是 **45 / 45** —— P1 把 Noul 计数与记录计数混同了。主张本身不受影响：日志中每一个 `Noul` 答案确实
都缺少该字段。P1 的冻结文本**未**被改动，因为它是一份历史审计产物。此处记录，而不是悄悄修正。
