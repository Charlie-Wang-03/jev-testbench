# jev-test

[English](README.md) | **简体中文**

一个可审计的实验台，用于把 **TypeSafe Jev** 作为 LLM 与 Agent 工作流中的「类型化概率决策原语」来研究。

Jev 不是聊天模型。它接收一段 `state` 和一组**类型化问题**，返回**带概率的结构化答案** —— 一个
`Choice` 标签连同分布、一个有序量表上的 `Score` 位置，或者一个 `Noul` 标量概率。它不生成散文、不
维持对话、请求之间没有任何记忆。来源见[什么是 Jev](#1-什么是-jev)。

本仓库就是这个原语的测量台。每一次真实 API 调用都会向一个只追加的 JSONL 日志写入且仅写入一行，
而所有文档里的每一句话都被标注为：厂商官方说法、设计假设、本地测量、本地推导，或局限性。

**状态：** `CORE_CAPABILITY_EXPLORATION_CLOSED` · **测试：** 975 个全部通过，完全离线 ·
**证据：** [42 条核心记录](results/usage.jsonl) + [12 条 P3 记录](results/p3_boundary_locus/usage.jsonl)

## 1. 什么是 Jev

**TypeSafe 自己的描述**（这不是本仓库的结论）：

> Jev 是一个类型化的概率决策模型 —— 一个把非结构化 state 转换为类型化概率决策的「System One」模型。

来源：<https://docs.typesafe.ai/llms.txt> · <https://typesafe.ai>

本实验台测量的是：这个原语**在这台机器上、用这个账号、在我们的输入上**做了什么。TypeSafe 发布的
性能或准确率说法，在本仓库中一律记为关于**他们**工作负载的 **OFFICIAL CLAIM（官方说法）**，绝不
会被表述成我们验证过的结论。

## 2. 这个仓库是什么

一个实验台 —— 不是 API 演示，不是排行榜，也不是通用准确率基准。它的全部价值来自一个产物的可信度：

| P3 权威日志 | [`results/p3_boundary_locus/usage.jsonl`](results/p3_boundary_locus/usage.jsonl) —— 12 条记录 |
| P3 日志 SHA-256 | `17f36f7551d598a4724f4557d8b235d810ec4fb259d8d4b842eabc8f34c5d78e` |

P3 出于同样的理由保留了自己的日志。详见[证据溯源](docs/EVIDENCE_PROVENANCE.md)。

## 3. 为什么存在

因为关于一个概率决策原语，真正值得问的不是「它好不好」，而是**「它到底做了什么，而我究竟能从
中得出什么结论」**。

- **不是 API 演示。** 这里没有任何内容是为了把产品展示得漂亮而写的。
- **不是排行榜。** 本实验台中不存在任何 ground truth，所以没有可用来排名的准确率分数。
- **不是通用基准。** 每一个数字都只描述一个 payload、一个账号、一次会话、一个模型版本。
- **以证据为准。** 失败的调用也是记录。负面结果被保留。一个既不新颖、也得不到自身数据支持的发现，
  会被正式写成「已否决（killed）」，而不是悄悄丢掉。

## 4. 我们测了什么

注册了 15 个实验，已运行 10 个。分两档：

**`core` —— 基础机制**

| 实验 | 调用数 | 测量内容 |
|---|---|---|
| `01_primitives` | 1 | 对同一个 state 在单次请求中同时取 `Choice` + `Score` + `Noul`。 |
| `02_structured_addressing` | 2 | 结构化 state 上的字段路径寻址 vs. 散文 state 上的描述式寻址。 |
| `03_parallel_questions` | 12 | 一次批量请求 vs. 同样的问法逐条分开发送，两个顺序对称的循环。 |
| `04_confidence` | 2 | 具体证据 vs. 模糊证据，仅依据 confidence 在代码中路由。 |

**`extended` —— 具体行为与已记录的限制**

| 实验 | 调用数 | 测量内容 |
|---|---|---|
| `05_speculative_fanout` | 6 | 一次请求携带两个分支的追问 vs. 依据首个答案再发第二次请求（staged）。 |
| `06_composite_scoring` | 3 | 四个原子 `Score` 问题**在 Python 中**合成为一个风险值，权重在运行前冻结。 |
| `07_instruction_precision` | 2 | 在逐字节相同的 82 字节 state 上，模糊 vs. 明确的决策边界。 |
| `12_function_routing` | 4 | 把 state 路由到一份运行前冻结的注册表中的函数名，再路由到闭集参数。 |
| `13_repeatability` | 5 | 把同一个逐字节相同的请求发送五次。 |
| `13b_ambiguous_repeatability` | 5 | 把已知会落在量表中段的 payload 发送五次。 |

**P3 —— 一次预注册的重复实验**（[设计](docs/experiments/P3_BOUNDARY_LOCUS_PREREGISTRATION.md) · [结果](docs/audits/P3_BOUNDARY_LOCUS_RESULT.md)）

实验 `07` 同时改动 *instructions* 与 *criteria*，把一个 `Noul` 从 0.75 移到 0.20，因此无法判断是
哪一个字段造成了这个位移。P3 把这两个字段做成 2×2 交叉，每个臂重复三次、共十二次调用，设计与阈值
在第一次请求之前就已冻结。

另有五个实验（`00_model_info`、`08_literal_reading`、`09_numeric_limits`、`10_state_length`、
`11_language_pair`）已注册但未运行。它们是一份可选的边界覆盖待办，不是阻塞项 —— `08` 和 `09` 的
用途是在本地把已记录在案的失效模式观察一次，而不是给模型打分。

## 5. 我们学到了什么

以下是最稳健的结果。除非特别标注，每一条都是**本地测量**。

**类型化输出的语义在本地干净地复现。** 42 条响应全部通过 schema 校验且只有类型化答案 —— 没有任何
自由文本字段。45 个 `Choice` 答案中，返回的标签每次都恰好是概率最高的选项；29 个 `Score` 答案中，
24 个在 0.006 以内复现了概率加权均值。`Noul` 答案不携带单独的 `confidence` 字段，因为只有两种结果
时，那一个数字已经描述了整个分布。*（这是对类型安全主张最弱的一种支持：它只说明在良性 payload 上
schema 合规，不说明事实正确性。）*

**在同一 workload 中，同 state 批处理显著降低了重复 state 的输入消耗。** 把 5 个问题针对同一个
state 放在**单次**请求里，消耗 **816** 输入 token；把同样的 5 个问题**分开发送**，消耗 **3,480**。
即 **4.26× 的合并输入比、76.55% 的输入 token 节省**，两个臂之间 **10 / 10** 选中值完全一致。
*这是一份「所有问题都读同一个 state」的 payload。它不是通用的批处理倍率，也不能与厂商自己公布的
倍率相比较 —— 那个数字描述的是另一种 workload。*

**Confidence 适合作为策略输入，但不是单条答案的正确性保证。** 官方文档把校准的适用范围限定在
**成组**预测上，并明确写道 confidence「描述的是模型的答案，而不是该答案正确的保证」—— 本仓库的两个
confidence 用例只是*说明*了这层限定，无法检验它。本地的警示样本：在 `06` 中，某个维度得分 1.62，
而它的 confidence 只有 **0.24**，这个维度却承载了该 state 综合风险值的 **97.4%**。

**指令与 criteria 的具体程度确实移动了其中一个 payload。** 在一个**逐字节相同**的 82 字节 state
上，模糊的决策边界返回 `Noul` **0.75**，明确边界返回 **0.20** —— 在 0–1 概率上位移 **0.55**。
两个臂都不是 ground truth，且一组配对不构成剂量—反应曲线。

**P3 无法把这个位移归因到任何一个字段。** 判定：
**`P3_KILL_NO_SINGLE_FIELD_ATTRIBUTION`**。仅改 instruction 的臂中位数 0.31，仅改 criteria 的臂
中位数 0.36 —— 两者都远离模糊基线（0.76），而彼此之间只差 **0.05**，相比之下端到端差距为 0.56。
预注册的判定规则否决了归因：没有任何一种「把某个单字段臂当作位移臂」的指派，能使其对侧落在模糊基线
附近。仅作描述性记录：仅 instruction 恢复了 80.4% 的差距，仅 criteria 恢复了 71.4%。
**零结果也是结果。**

**重复同一个请求时，稳定标签之下分布仍在移动。** 在十次逐字节相同的调用中，胜出的 `Choice` 标签
从未切换，但其下的前二名间距最多移动了 0.07，并且有一次重复出现了精确并列。这个*现象*是真实的；
它不是新发现，P2 已将其作为非新颖项否决 —— 见下文。

**路由与授权是两个独立的工程层次。** 在 `12_function_routing` 中，模型 4 / 4 次匹配到预期函数、
4 / 4 次匹配到预期参数 —— 而一份运行前冻结的策略**扣下了全部**路由，因此没有任何 handler 被执行。
是否行动是在模型回答之后、由 Python 决定的。任何把「有信心的路由」当作行动许可的系统，都已经删掉
了产生这个结果的那一层。

**而最重要的部分是 —— 若干个看起来很漂亮的发现被刻意否决了。** P2 用同一把尺子审查了每一个候选：
*它相对于 TypeSafe 的公开材料是否新颖，**并且**是否得到我们自身数据的支持？* 七个候选被淘汰，其中
包括本地效应量最大的两个：

| 被否决的候选 | 原因 |
|---|---|
| 「标签稳定、分布移动」 | 非新颖 —— 官方已蕴含此意，且公开复现的数据量比我们更大。 |
| 批处理降低输入 token | 预期的同 state 摊销；公开测量走得更远（它们变化了批大小）。 |
| 0.75 → 0.20 的指令效应 | 已记录在案的失效模式的直接实例，且文档已给出补救办法。 |
| 模糊用例越过了 0.60 门槛 | 纯粹是对**我们自己**常数的阈值算术 —— 该表达式精确复现了 0.61。 |
| Fan-out 用输入换输出 | 通用的推测执行权衡 —— 且在本产品的价格表中，「浪费掉」的资源是输出 token，定价为零。 |
| `confidence` 无法由日志中的 `probabilities` 重算 | API 两位小数舍入的产物 —— 是我们*记录*的极限，不是模型的行为。 |
| 每一条正确路由都被扣下 | 这是我们自己的 Python 策略，源码注释里就是这么写的。 |

> **没有任何候选因为不好看而被否决，也没有任何候选因为有意思而被保留。**

唯一通过审查的候选就是上面那个 P3 问题 —— 而 P3 随后返回了零结果。**本仓库目前报告不出任何既新颖、
又得到自身数据支持的 Jev 专有发现。** 这就是证据的诚实状态，而这正是这项练习的意义。

## 6. 你能复现什么

### 完全离线 —— 不需要 API key

```console
uv sync --locked
uv run pytest                                    # 975 个测试，socket 被封锁
uv run python -m jev_lab report                  # summary.csv, summary.md
uv run python -m jev_lab snapshot                # capability_snapshot.md
uv run python -m jev_lab final-report            # JEV_LOCAL_EVALUATION_FINAL.md
```

测试完全不触碰网络 —— 测试套件直接封锁 socket，因此一次意外的 API 调用会直接失败，而不是花钱。所有
派生报告都从已提交的权威日志重建，所以其中的数字不可能与它们所描述的记录发生漂移。

### 真实复现 —— 需要 TypeSafe 账号

```console
uv run python -m jev_lab list                    # 实验、调用上限、凭据状态
uv run python -m jev_lab run 01_primitives       # 单个实验，默认上限 8 次调用
uv run python -m jev_lab run-all --tier core     # 整档运行；没有显式预算时拒绝启动
```

**这些命令会花真钱。** `run` 默认硬上限 8 次 API 调用；`run-all` 在 `--max-requests` 未覆盖该档
case 数时拒绝启动。见[凭据](docs/guides/credentials.zh-CN.md)与[复现](docs/guides/reproducibility.zh-CN.md)。

> **冻结的测量是历史测量，不是每次未来运行都必须复现的黄金输出。** 一次全新的真实运行不一定会复现这
> 些数字。模型别名 `jev-latest` 可能移动，账号与会话不同，而且这是一个概率模型 —— 在本仓库中，逐字
> 节相同的请求返回了形状不同的分布。复现*方法*才是目标；复现*数字*不是这个设计能够承诺的事。

## 7. 你**不能**从这个仓库得出的结论

直白列出，因为这是全文最重要的一节：

- **没有通用准确率。** 本实验台中不存在任何 ground truth。「4 / 4」是合成用例上的计数，永远不是比率。
- **没有校准验证 —— 两个方向都没有。** 这里不存在结果发生率，因此本仓库绝不能被引用为验证*或*证伪了
  校准。
- **没有模型延迟基准。** 延迟是记录，不是基准。没有声称任何加速，也没有把任何臂称为更快。
- **没有确定性保证 —— 也没有非确定性保证。** 两个 payload 上的少数几次重复不构成确定性裁决。
- **没有通用批处理倍率。** 4.26× 是「所有问题共享同一个 state」的那一份 payload 的属性。
- **没有广泛的幻觉基准。** 这里不探测事实正确性；「不会幻觉」这个说法必须带上厂商自己标注的
  「非经验性」限定。
- **没有生产安全认证。** 所有 handler 都是惰性的。这里没有任何内容能证明某种模式对真实系统、真实客户
  数据或真实资金是安全的。
- **没有厂商说法的裁决。** 官方数字被记为关于 TypeSafe 工作负载的说法，绝不会被改写成我们测量过的
  东西。

成本数字是来自单一价格表的**本地估算**。TypeSafe Console 账单才是权威记录。

## 基本规则

- 官方 TypeSafe 文档是产品语义的唯一权威：<https://docs.typesafe.ai/llms.txt>。本地观察若与文档
  冲突，会被记为一个 finding，而不是被悄悄「修正」。
- 官方说法与本地测量分开记录，每个结果都会说明自己属于哪一类。
- **代码做算术，Jev 做语义判断。** 绝不让 Jev 去计数、求和、比较、插值或计算日期差。
- Token 计数是 API 在 `usage` 中返回的值。**这里没有任何东西在估算 token。**
- 同时记录 `model_requested` 与 `model_resolved`，因为别名会移动。
- `results/usage.jsonl` 只追加。不会重写、重排或删除任何内容 —— 包括失败调用的行。失败的调用也是数据。
- 所有 state 都是合成的。不含任何真实个人、客户或专有数据。
- 本仓库中永远没有密钥。
